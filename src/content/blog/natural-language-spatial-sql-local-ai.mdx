# Natural Language Spatial SQL, Running Locally

Spatial databases are powerful, but they often remain locked behind SQL fluency. The prototype I built explores a simple question: what if a territorial analyst could ask a spatial database a question in natural language and receive a valid query, a table, and a map in the same workflow?

The demo uses an airports dataset, but the pattern is broader. A user can ask, for example, "show me the five airports in Japan with the highest elevation." An AI agent translates the request into SQL, runs it against the spatial database, and displays the result as both records and geometry.

## Why Local Matters

The architecture is intentionally local-first. The database and the language model run on the same machine through Ollama, which keeps sensitive spatial data close to the user and avoids unnecessary cloud dependencies.

That design choice matters for public agencies, consulting teams, and research groups that work with infrastructure, facilities, demographic layers, or operational assets. In those contexts, geospatial AI is not only about model capability. It is also about governance, auditability, and control over data movement.

## The Technical Core

The prototype combines three ideas:

1. **Natural-language intent parsing**: the user asks for an analysis in ordinary language.
2. **Spatial SQL generation**: the agent converts intent into executable SQL.
3. **Fast analytical execution**: DuckDB with spatial extensions returns results in seconds.

This creates a compact architecture for interactive spatial analytics. It does not replace GIS expertise; it makes the first analytical move faster and easier to inspect.

## Where This Can Go

The next version should make database connection easier, support a more conversational query flow, add drawing tools for spatial filters, and generate charts or reports from the same query results. The most useful version of this type of tool is not a chatbot sitting next to a map. It is an orchestrated interface where chat, table, geometry, and analytics stay synchronized.

# SQL espacial en lenguaje natural, ejecutado localmente

Las bases de datos espaciales son potentes, pero muchas veces quedan bloqueadas detrás de la fluidez en SQL. El prototipo que construí explora una pregunta simple: ¿qué pasaría si una analista territorial pudiera hacer una pregunta en lenguaje natural a una base de datos espacial y recibir una consulta válida, una tabla y un mapa dentro del mismo flujo?

La demo usa un conjunto de datos de aeropuertos, pero el patrón es más amplio. Una persona puede pedir, por ejemplo, "muéstrame los cinco aeropuertos de Japón con mayor elevación". Un agente de IA traduce la solicitud a SQL, la ejecuta contra la base de datos espacial y muestra el resultado como registros y geometría.

## Por qué importa lo local

La arquitectura prioriza la ejecución local. La base de datos y el modelo de lenguaje corren en la misma máquina mediante Ollama, lo que mantiene los datos espaciales sensibles cerca de quien consulta y evita dependencias innecesarias de la nube.

Esa decisión de diseño importa para agencias públicas, equipos consultores y grupos de investigación que trabajan con infraestructura, equipamientos, capas demográficas o activos operacionales. En esos contextos, la IA geoespacial no se trata solo de capacidad del modelo. También se trata de gobernanza, auditabilidad y control sobre el movimiento de datos.

## El núcleo técnico

El prototipo combina tres ideas:

1. **Interpretación de intención en lenguaje natural**: la persona solicita un análisis en lenguaje común.
2. **Generación de SQL espacial**: el agente convierte la intención en SQL ejecutable.
3. **Ejecución analítica rápida**: DuckDB con extensiones espaciales devuelve resultados en segundos.

Esto crea una arquitectura compacta para analítica espacial interactiva. No reemplaza la experiencia GIS; hace que el primer movimiento analítico sea más rápido y más fácil de inspeccionar.

## Hacia dónde puede avanzar

La siguiente versión debería facilitar la conexión a bases de datos, soportar un flujo de consulta más conversacional, agregar herramientas de dibujo para filtros espaciales y generar gráficos o reportes desde los mismos resultados. La versión más útil de este tipo de herramienta no es un chatbot al lado de un mapa. Es una interfaz orquestada donde chat, tabla, geometría y analítica permanecen sincronizados.
